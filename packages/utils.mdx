`@typescript-eslint/utils` is the standard package for building custom ESLint rules and plugins that work with TypeScript. It provides typed wrappers around ESLint's APIs, utilities for AST operations, and the `RuleCreator` factory used by typescript-eslint's own rules.

<Note>
  If you need to work with TypeScript **type information** inside rules (beyond AST-level checks), also install [`@typescript-eslint/type-utils`](/packages/type-utils). That package is kept separate so `@typescript-eslint/utils` does not need a hard dependency on `typescript`.
</Note>

## Installation

<CodeGroup>

```bash npm
npm install --save-dev @typescript-eslint/utils
```

```bash yarn
yarn add --dev @typescript-eslint/utils
```

## Exports

| Name              | Description                                                                                                                                                                             |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AST_NODE_TYPES`  | Enum with the name of every AST node type produced by `@typescript-eslint/typescript-estree`.                                                                                           |
| `AST_TOKEN_TYPES` | Enum with the name of every AST token type produced by `@typescript-eslint/typescript-estree`.                                                                                          |
| `ASTUtils`        | Helpers for operating on the ESTree AST, plus the [`@eslint-community/eslint-utils`](https://www.npmjs.com/package/@eslint-community/eslint-utils) package typed for `TSESTree` nodes.  |
| `ESLintUtils`     | Helpers for creating ESLint rules with TypeScript, including `RuleCreator` and `getParserServices`.                                                                                     |
| `JSONSchema`      | Strict types for the JSON Schema v4 spec — the version ESLint uses to validate rule options schemas.                                                                                    |
| `ParserServices`  | Typing for the parser services provided when parsing files with `@typescript-eslint/typescript-estree`.                                                                                 |
| `TSESLint`        | ESLint types re-exported and correctly typed for use with `TSESTree` nodes.                                                                                                             |
| `TSESLintScope`   | The [`eslint-scope`](https://www.npmjs.com/package/eslint-scope) package, typed to work with both `TSESTree` and `TSESLint`.                                                            |
| `TSESTree`        | Types for the TypeScript-flavored ESTree AST produced by `@typescript-eslint/typescript-estree`.                                                                                        |
| `TSUtils`         | Lower-level TypeScript utility helpers.                                                                                                                                                 |

## `ESLintUtils`

### `RuleCreator`

`RuleCreator` is the standard way to define a typed custom ESLint rule. Call it with a function that maps a rule name to a documentation URL, and it returns a `createRule` factory you use for each rule in your plugin.

```ts
import { ESLintUtils } from '@typescript-eslint/utils';

const createRule = ESLintUtils.RuleCreator(
  name => `https://example.com/rules/${name}`,
);

export const myRule = createRule({
  name: 'my-rule',
  meta: {
    type: 'problem',
    docs: {
      description: 'Disallow use of console.log in production code.',
    },
    messages: {
      noConsoleLog: 'Unexpected console.log call.',
    },
    schema: [],
  },
  defaultOptions: [],
  create(context) {
    return {
      CallExpression(node) {
        if (
          node.callee.type === 'MemberExpression' &&
          node.callee.object.type === 'Identifier' &&
          node.callee.object.name === 'console' &&
          node.callee.property.type === 'Identifier' &&
          node.callee.property.name === 'log'
        ) {
          context.report({ node, messageId: 'noConsoleLog' });
        }
      },
    };
  },
});
```

When you do not need a documentation URL, use the static `withoutDocs` method:

```ts
const myRule = ESLintUtils.RuleCreator.withoutDocs({
  meta: {
    type: 'suggestion',
    messages: { myMessage: 'Something.' },
    schema: [],
  },
  defaultOptions: [],
  create(context) {
    return {};
  },
});
```

### `getParserServices`

`getParserServices` retrieves the typed parser services from the rule context. Use it inside any rule that needs access to the TypeScript type checker or the bidirectional AST node maps.

```ts
import { ESLintUtils } from '@typescript-eslint/utils';

// Overload 1: requires full type information (throws if unavailable)
const services = ESLintUtils.getParserServices(context);

// Overload 2: explicit — throws if type info is absent
const services = ESLintUtils.getParserServices(context, false);

// Overload 3: returns partial services; does NOT throw if type info is absent
const services = ESLintUtils.getParserServices(context, true);
```

The returned `ParserServices` object provides:

| Property                | Type                                      | Description                                           |
| ----------------------- | ----------------------------------------- | ----------------------------------------------------- |
| `program`               | `ts.Program`                              | The TypeScript `Program` for the file being linted.   |
| `esTreeNodeToTSNodeMap` | `WeakMap<TSESTree.Node, ts.Node>`         | Maps ESTree AST nodes to the corresponding TS nodes.  |
| `tsNodeToESTreeNodeMap` | `WeakMap<ts.Node, TSESTree.Node>`         | Maps TypeScript AST nodes back to ESTree nodes.       |

<Warning>
  Calling `getParserServices` (without `true`) in a rule that is not configured with type information will throw an error at lint time. Mark such rules with `meta.docs.requiresTypeChecking = true` so tooling can warn users.
</Warning>

Example — accessing the type checker inside a rule:

```ts
import { ESLintUtils } from '@typescript-eslint/utils';

const createRule = ESLintUtils.RuleCreator(
  name => `https://example.com/rules/${name}`,
);

export const requiresTypeInfo = createRule({
  name: 'requires-type-info',
  meta: {
    type: 'problem',
    docs: {
      description: 'Example rule that uses type information.',
      requiresTypeChecking: true,
    },
    messages: { example: 'Example message.' },
    schema: [],
  },
  defaultOptions: [],
  create(context) {
    const services = ESLintUtils.getParserServices(context);
    const checker = services.program.getTypeChecker();

    return {
      Identifier(node) {
        const tsNode = services.esTreeNodeToTSNodeMap.get(node);
        const type = checker.getTypeAtLocation(tsNode);
        // use `type` here...
      },
    };
  },
});
```

### `nullThrows`

Asserts that a value is not `null` or `undefined`, throwing with a clear message if it is. Used throughout typescript-eslint internals.

```ts
import { ESLintUtils } from '@typescript-eslint/utils';

const symbol = ESLintUtils.nullThrows(
  type.getSymbol(),
  ESLintUtils.NullThrowsReasons.MissingToken('symbol', 'type'),
);
```

## `ASTUtils`

`ASTUtils` re-exports helpers from `@eslint-community/eslint-utils` with proper `TSESTree` types, plus its own predicates and utilities.

### Node type guards

These predicates narrow `TSESTree.Node` to a specific node type:

```ts
import { ASTUtils, AST_NODE_TYPES } from '@typescript-eslint/utils';

// Check for a single node type
const isIdentifier = ASTUtils.isNodeOfType(AST_NODE_TYPES.Identifier);
isIdentifier(node); // => node is TSESTree.Identifier

// Check for any of multiple node types
const isFunction = ASTUtils.isNodeOfTypes([
  AST_NODE_TYPES.ArrowFunctionExpression,
  AST_NODE_TYPES.FunctionDeclaration,
  AST_NODE_TYPES.FunctionExpression,
] as const);
isFunction(node); // => node is TSESTree.ArrowFunctionExpression | TSESTree.FunctionDeclaration | TSESTree.FunctionExpression

// Check type + property conditions simultaneously
const isOptionalCallExpression = ASTUtils.isNodeOfTypeWithConditions(
  AST_NODE_TYPES.CallExpression,
  { optional: true },
);
```

### Predicate helpers

`ASTUtils` exports a number of ready-made predicates built with the helpers above:

| Export                         | What it checks                                                   |
| ------------------------------ | ---------------------------------------------------------------- |
| `isFunction`                   | `ArrowFunctionExpression`, `FunctionDeclaration`, `FunctionExpression` |
| `isFunctionType`               | TypeScript function-type node kinds (e.g. `TSFunctionType`)      |
| `isFunctionOrFunctionType`     | Either of the above                                              |
| `isIdentifier`                 | `Identifier` node                                                |
| `isTypeAssertion`              | `TSAsExpression` or `TSTypeAssertion`                            |
| `isLoop`                       | Any loop statement                                               |
| `isConstructor`                | A `constructor` method definition                                |
| `isOptionalCallExpression`     | An optional call (`foo?.()`)                                     |
| `isLogicalOrOperator`          | A `\|\|` logical expression                                      |
| `isAwaitExpression`            | `AwaitExpression` node                                           |
| `isOptionalChainPunctuator`    | A `?.` punctuator token                                          |
| `isNonNullAssertionPunctuator` | A `!` punctuator token                                           |

## `TSESTree` types

`TSESTree` is re-exported from `@typescript-eslint/typescript-estree`. Import it from `@typescript-eslint/utils` to get correctly typed ESLint interfaces alongside it.

```ts
import type { TSESTree } from '@typescript-eslint/utils';

function visitNode(node: TSESTree.Node): void {
  if (node.type === 'Identifier') {
    // node is narrowed to TSESTree.Identifier
    console.log(node.name);
  }
}
```

## `TSESLint` types

`TSESLint` re-exports ESLint's core types with corrections for TypeScript usage. The most commonly used are `TSESLint.RuleContext`, `TSESLint.RuleModule`, and `TSESLint.Linter`.

```ts
import type { TSESLint } from '@typescript-eslint/utils';

type MyRuleContext = TSESLint.RuleContext<'myMessage', [{ strict: boolean }]>;
```
